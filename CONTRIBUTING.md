# Contributing to Verve N Veda

Thank you for your interest in supporting Verve N Veda.

This repository serves as the public landing site for a broader collection of educational, creative, civic, cultural, wellness, and community resources.

## Before Contributing

Please review:

- `README.md`
- `LICENSE.md`
- `SECURITY.md`
- `THIRD_PARTY_NOTICES.md`

## Contribution Priorities

Contributions are most helpful when they improve:

- Accessibility
- Mobile responsiveness
- Clear navigation
- Semantic HTML
- Performance
- Broken-link repair
- Privacy-conscious behavior
- Search discoverability
- Documentation
- Browser compatibility

## Design Guidance

Please preserve the established Verve N Veda identity unless a redesign has been explicitly approved.

Preferred characteristics include:

- Clean, centered layouts
- Crisp, readable typography
- Parchment and midnight tones where appropriate
- Restrained decorative detail
- Consistent spacing and proportion
- Accessible contrast
- Responsive behavior
- Lightweight implementation

Avoid introducing unnecessary frameworks, trackers, advertisements, or external dependencies.

## Technical Guidance

Preferred implementation:

- Standard HTML
- Standard CSS
- Vanilla JavaScript
- GitHub Pages compatibility
- Local storage for local-only features when appropriate
- Graceful operation without third-party services

## Accessibility

New work should aim to include:

- Keyboard-accessible controls
- Visible focus states
- Meaningful heading order
- Alt text for informative images
- Labels for form controls
- Adequate color contrast
- Reduced-motion consideration
- Responsive text and touch targets

## Security and Privacy

Do not submit:

- Passwords
- API keys
- Private user information
- Tracking scripts without approval
- Sensitive datasets
- Unlicensed copyrighted assets
- Code that sends personal data to third parties without clear disclosure

Security vulnerabilities should be reported through the process in `SECURITY.md`, not through a public issue.

## Pull Requests

A useful pull request should:

1. Explain the problem being solved.
2. Describe the proposed change.
3. Keep unrelated edits separate.
4. Preserve existing working features.
5. Test links and responsive behavior.
6. Include screenshots when visual changes are significant.
7. Note any new third-party code, fonts, images, or licenses.

## Content Contributions

Public-facing content should be:

- Accurate
- Respectful
- Clearly written
- Properly attributed
- Suitable for a broad audience
- Free of discriminatory or harassing material

## Final Review

All contributions remain subject to project-owner review and may be edited, declined, or postponed to preserve the site's direction, safety, and consistency.
