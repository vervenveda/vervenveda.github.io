# Repair 09 — Mapping Gap Report

The ecosystem already contains enough material that the next priority should be **metadata depth**, not automatically building more games.

## Ready for objective-aware recommendation

High-confidence source metadata exists for:
- Kindergarten core/practice apps;
- Elementary K–5 games/labs in the current Elementary manifest;
- Arcade word/logic/strategy games;
- ProReSources tools;
- Khaemenes Linguistics / Polyglot;
- Aurora optional wellness/creative resources;
- ARSHIF archive and preference-gated study resources;
- Medicament High School Health / PE resources after Repair #8;
- Solanar and River-to-Road at verified hub level.

## Important gaps

### Preschool

Crechè's 52 adventures are currently represented to Mentor mainly through the Adventure Garden catalog. The garden can be aligned broadly to early learning, but the individual adventures need their own catalog metadata before a lesson-specific Mentor should choose one by objective.

### Bazaar Art

The current Mentor role is a provisional root anchor. Individual courses/studios should be enumerated before Mentor claims “this Art 201 activity teaches objective X.”

### Solanar

The Observatory root is verified and maps cleanly to weather/Earth-system inquiry. Its deeper apps/courses should receive a deep manifest before child-resource precision is claimed.

### River-to-Road

The root maps strongly to environmental stewardship and service learning. Event/tool/resource-level mappings await deep inventory.

### Firmament

Law/civics can route to the verified root research/legal-information hub. Deeper child resources need their own manifest pass.

### Finance

The central repository registry currently treats Finance as discovered rather than recommendable because a valid Mentor source manifest is not yet promoted. Do not bypass that guardrail merely because financial-literacy objectives exist.

### Music / The Refrain

Music objectives are included in the taxonomy, but specific Refrain course/studio mappings should be promoted only from verified source-owned manifest metadata.

## Build decision

Before building a new game, ask:

1. Is there already a resource whose `skills`, `domains`, or content serve this objective?
2. Is it manifested deeply enough for Mentor to select it?
3. Is the missing piece actually a new activity, or only metadata/routing?
4. Does the lesson need direct practice, a creation tool, a reference source, a support routine, or transfer practice?
5. Would a new resource duplicate an existing one?

This is the operating purpose of Repair #9.
